## 재현 명령

저장소 루트에서 ZIP의 Python3.11 환경을 사용한다. `RADAR_VISION_ROOT`는 원본 Vision 작업 폴더이다. 출력 폴더는 기존 후보를 덮지 않는 새 이름이어야 한다.

```sh
python vision/generate_photo_mcp.py --source .demo/vision-debug/repro.jpg --rois .demo/vision-debug/rois.json --output vision/data/<new_run> --count 600
# 위 생성물은 train-only. 추가 원본 train과 소비된 개발 val을 labels.csv에 별도 역할로 연결한 뒤:
OMP_NUM_THREADS=4 PYTORCH_ENABLE_MPS_FALLBACK=1 python vision/train_mcp_ocr_v2.py --data vision/data/photo_aug_20261112 --output vision/checkpoints/<new_candidate> --init-checkpoints "$RADAR_VISION_ROOT/vision/checkpoints/mcp_ocr_v3" --epochs 16 --batch 32 --lr 0.0002 --device mps --augment --camera-preprocessing --camera-validation
```

인수 상태: 로컬 합성·후보 학습은 수행했으나 독립 새 실카메라 평가·후보 채택·외부 리뷰·전용 커밋/PR은 미실행이다. 상태는 verifying 유지, done으로 표시하지 않는다.

## 빛번짐·실촬영·단계 분리 평가 후속 (진행 중)

### 공간과 원본 보존

디스크가 다시0에 도달해 파일 생성이 실패했다. `yolo_camera` 원본과 SHA-256이 같은 `yolo_camera_confirmed`/`yolo_blind_v2` 이미지380개(840,150,550 bytes)를 원본과 같은 저장 블록을 참조하는 hardlink로 바꿨다. 원본·각 경로의 파일명·내용·라벨을 보존하고 검사기의 경로 내부 제약도 유지했다. `.demo/data-deduplication.json`에 기록했다. 학습 원본은 불변으로 취급해야 한다.

### 합성

`camera_effects.py`에 다중 크기 highlight bloom, 노출·포화, 방향성 반사띠, 센서 노이즈, JPEG65–95를 추가했다. `generate_photo_mcp.py --glare --count300 --seed20261112`로 `photo_glare_20261112` 300쌍 생성, 전처리 실패0. 모든 파생본 train-only. 효과 파라미터·원본 해시·좌표·정답 기록, preview0000 육안 확인. 완전히 지워진 숫자를 맞히게 만드는 음성적 정답 학습은 수행하지 않았다.

### 실제 동기화 촬영

사용자가 /cockpit?display=training과 별도 웹캠을 준비했다. 107/12300을 실제 카메라 sentinel 프레임에서 육안 확인해 카메라 대상과 선택한 디스플레이의 대응을 확인했다. `collect_ack_frames.py`는 선택 display의 동일 seq/값 render ACK가1초 연속 유효한 뒤 추가1초 이후 시작된 프레임만 저장한다. 프레임/metadata SHA-256 일치·최대6초 신선도·서로 다른 프레임·64MiB 공간 하한을 검사한다. 모든 예정 프레임을 원본으로 저장하며 탐지·OCR 실패를 저장 기준에서 제외하지 않는다. 정답은 모의 디스플레이의 명령과 ACK에서 얻고 OCR 예측으로 라벨링하지 않는다.

첫 세션 `live_bloom_train_20261112`: 정면 현재 빛번짐,20개 조합×3장=60/60,20개의 상관된 숫자 그룹. 종료 후270/03000 복원 command 및 실제 render ACK 확인. role=train. 독립 최종 시험으로 사용하지 않는다. 두 번째 각도/거리 조건 변경을 사용자에게 요청했고 확인 대기 중이다. 새 개발·최종 촬영은 아직 수행하지 않았다.

### 진단과 구현 상태

`evaluate_capture_session.py`: raw 예정 장수·저장 장수·탐지·전처리 성공·출력/보류·맞은 출력·틀린 출력을 별도 집계한다. 현재 전처리 성공은 crop의 물리적 완전성을 보증하지 않는다. 정확한 잘림 평가에는 별도 box 정답 주석이 필요하다. 누락·탐지 실패를 전체 분모에서 제거하지 않는다. 프레임은 독립 표본으로 표현하지 않는다.

정면 train60장의 진단 결과 v3 CNN 단독: 탐지46/60, HDG/ALT 모두 출력0(전부 보류). 기존 character_v2 후보 단독은 별도 탐지 실행47/60, HDG 출력11중 정답4/오답7, ALT 출력2중 정답2. 두 실행의 탐지 결과가 다르므로 동일 crop 고정 비교로 해석하지 않는다. 이 후보를 실제 실행에 적용하지 않았다. 현재 운영의 Apple Vision fallback과 구분되는 CNN 단독 진단이다.

`prepare_live_training.py`에 train/development 세션 역할·중복 프레임 검사, 원본 탐지 실패 audit, 별도 정답 기반 crop 준비 기능을 추가했다. `train_character_ocr.py --init`은 같은 전처리 계약인 기존 가중치에서 별도 후보를 학습할 수 있다. 이 후속 새 후보 학습/최종 평가는 아직 미실행이다.

검증: Vision API/합성/신선도 회귀64개 통과. 빛번짐의 seed 재현·주변 광 확산, 오래되거나 파일/metadata가 불일치한 프레임 거부 포함. 기존 테스트를 보존했다. 모델·원본·진단 영상은 Git 제외이며 미커밋 상태 유지. 사용자 하드웨어 조건 변경 확인 후 두 번째 촬영→새 개발 데이터 분리→학습 후보 동결→새 최종 촬영 순서로 이어간다.

## 실제 각도 추가·개발 분리·동결 최종 평가 결과

### 촬영 및 실패 보존

두 번째 각도/거리 train 세션은 예정60장 중50장 저장 후 프레임 신선도 검사에서 중단했다. OCR 처리 대기열과 종료 대기 중인 구 서버가 오래된 프레임을 기록하던 문제가 있었다. 새 서비스는 nonblocking 처리 슬롯으로 중복 요청을429로 즉시 거부하고, raw frame/metadata는 탐지 전에 원자적으로 기록한다. 이전 서비스는 종료했으며 오래된/불일치 프레임은 수집에서 거부됐다. 부족한4조합은 별도 retry 세션12/12장으로 촬영했다. 원래 누락10장을 분모에서 숨기지 않았다. 각도 조건 전체62장에는 중복 숫자 그룹이 포함된다.

실제 train: 정면60 + 각도50 + retry12 =122장. 개발: 다른 물리 위치에서12조합×2=24/24장. 모델/코드 동결 후 최종: 다시 다른 위치·밝기에서 새12조합×3=36/36장. 모든 촬영 종료 후270/03000 복원 command와 render ACK를 확인했다. 최종36장도12개 상관된 설정 그룹이며 독립36개 장면으로 주장하지 않는다.

### 데이터와 분리 원인

탐지/전처리로 완전 쌍을 만들 수 있던 train은99/122쌍. 빛번짐 합성300쌍과 합쳐 train798crop, 개발48crop을 준비했다. 최종 이미지는 학습/개발에 넣지 않았다. 실제 개발 contact sheet에서 ALT 옆 창 테두리가6번째 glyph로 남고, 일부0끼리는 열 투영에서 붙는 것을 확인했다. V3/V4 전처리를 별도 메타데이터 값으로 추가해 기존 모델의 의미를 바꾸지 않았다. V4에서도 실제로 합쳐진 글자나 누락은 보류한다. 학습 crop798 중 glyph 분리 실패428개는 학습 manifest에 남겨 optimizer에서 제외했고, 실제 사용한 glyph는1520개다. 합성 이미지를 생성한 장수와 실제 학습에 들어간 장수를 구분한다.

character_v2를 초기값으로 CPU12epochs/batch32/lr.0001/seed42 추가 학습했다. 개발 결과만으로 오답 출력 최소화→필드별 맞는 출력 비율→문자열 일치 순으로 후보를 선택했다. 개발24장씩에서 raw exact HDG24/24, ALT23/24; 실제 출력은 HDG24/24, ALT18/24, 오답0. 이것을 독립 최종 정확도로 표현하지 않는다.

### 동결 최종 평가 (36장, 12설정 그룹)

체크포인트와 detector/전처리/평가 코드 해시를 최종 촬영 전에 `glare_character_frozen_20261112/freeze.json`에 고정하고 변경 없음을 확인했다. 동일 raw-session hash와 동일 ROI를 사용해 비교했다. 아래 숫자는 전체 예정36장 기준이며, 값은 모두 이미지로만 추론했다.

| 구성 | HDG 맞는 출력 / 오답 / 보류 | ALT 맞는 출력 / 오답 / 보류 |
| --- | --- | --- |
| 기존 v3 CNN 단독 |0 / 5 / 31|0 / 0 / 36|
| 새 character CNN 단독 |36 / 0 / 0|29 / 0 / 7|

### 실행·검증·복원

`character_runtime.py`는 prepare_camera_crop→checkpoint에 명시된 CharacterOCR를 연결한다. model SHA 불일치 시 시작 실패, 원본 v3 fallback 선택 유지. `.demo/active-vision.json`에 동결 모델/해시를 기록했고 통합 런처가 이를 읽는다. 현재8766 health에서 character_cnn_glare_v4/ready/control_enabled=false 확인. 진단 raw frame 저장 환경변수는 활성 서비스에서 제거했다. 기존 비행 DB/음성/리포트 설정을 바꾸지 않았다.

실행 중인 새 서비스에 흰색/검은색 무정보 JPEG를 각각 전송해 ROI와 양쪽 숫자가null임을 확인했다. API 기반 진단이며 브라우저 시각 확인·3프레임 안정화 이후 출력 커버리지의 완전한 인수는 미실행이다. Vision 회귀71개 통과, 셸 문법 및git diff --check 통과. 원본 모델·중간 후보·실패 로그·전체 raw 세션 보존, Git에는 코드와 익명화 수치만 포함한다.
