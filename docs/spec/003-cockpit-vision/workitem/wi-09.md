# SPEC-003-WI-09: 이동 중 ROI 갱신과 연속 재탐색

## 요청·원인

2026-11-16 사용자 요청: 인식 시작 후 Cockpit이 움직여도 인식 영역이 따라가야 하며 화면이 멈추지 않아야 한다. 기준은 비율 수정 전용 브랜치 `codex/cockpit-proportions-20261116`의 `9aff3e8`이다.

원인 확인:

1. Operation은 최초 자동 탐지 좌표를 보관한 뒤 ±60px의 동일 크기 템플릿 이동만 검사했다. 큰 이동·확대·회전 후 다시 자동 탐지하지 않았다.
2. 추적이 성공해도 서버가 현재 ROI를 응답하지 않고 브라우저도 최초 박스를 계속 그렸다.
3. visibilitychange에서 카메라를 중지해 사용자가 Cockpit 탭으로 옮기면 인식이 종료됐다.
4. 초기 탐지 8회 실패, 같은 video.currentTime, 600프레임 제한 및 watchdog 이후 재시작 거부도 연속 사용을 끊을 수 있었다.

## 구현

- `backend/app/services/demo/tracking.py`: AUTO는 각 새 이미지에서 기존 Vision 자동 영역 탐지를 다시 수행한다. 목표값·이전 좌표를 탐지 실패의 대체값으로 쓰지 않는다. MANUAL은 숫자 밖의 패널 패턴을 추적하며 성공 시 참조 영상과 좌표를 갱신하여 누적 평행이동을 따라간다. 수동 모드의 큰 회전·배율 변화 복구는 보장하지 않는다.
- `backend/app/services/demo/adapters.py`: 현재 ROI로만 OCR을 수행하고 `rois`/`tracking_status`를 반환한다. 놓치면 OCR에 이전 좌표를 넣지 않고 null 관측·DEGRADED 상태를 저장한다. 동일 token에서 다시 찾을 수 있고 큰 이동·배율 변화·놓침·stale·일시 중단 뒤에는 3회 확인을 초기화한다. 600프레임 강제 종료를 제거했으며 cache 크기·기존 보존/신선도 검사·중복/역순 거부는 유지한다.
- `frontend/src/DemoPanel.jsx`: 응답의 현재 ROI로 박스를 갱신한다. 초기 탐지도 반복 루프 안에서 계속하고 대기·놓침·일시적 실패는 보류 상태로 재시도한다. 탭이 숨겨져도 카메라를 의도적으로 종료하지 않으며 마이크 입력 취소는 유지한다. 실제 새 프레임이 없으면 결과·박스를 비우고 채널 상태를 낮춘다. 오래된 generation 응답은 적용하지 않는다.
- `contracts/demo-camera-tracking.md`: 응답 좌표계, TRACKING/SEARCHING과 최종 판정의 구분, 재개·보류 동작을 기록한다.
