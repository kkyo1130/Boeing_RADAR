# SPEC-009-WI-06: GLB 기반 조종석 메시

- 사용자 요청: 현재 조종석을 `.glb` 모델로 구현한다. 기존 사진 기반 MCP의 세 선택값과 수동 조작을 유지한다.
- 기준: dev `2e3dd77`; 브랜치 `codex/cockpit-glb`.
- 최종 범위: MCP 외 좌우 계기판·창문·조종간·페달·센터 콘솔·좌석·오버헤드까지 포함한 전체 조종석 메시. 제조사 CAD 정밀 복제나 항공기 제어·서버 판정 변경은 제외한다.

## 구현

`frontend/scripts/build-cockpit.mjs`는 Three.js geometry를 GLTFExporter로 바이너리 GLB에 저장한다. 패널, 노브, 버튼, 나사, 표시창 노드를 분리하며 `public/models/cockpit.glb`는 약5.3MB다. `Cockpit3D.jsx`는 GLTFLoader로 실제 파일을 읽고 React 상태에 연결된 숫자/라벨 평면을 추가한다. OrbitControls 회전·확대와 정면 초기화, Raycaster 숫자 클릭 편집/노브 좌우 클릭 증감을 제공한다. 기존 입력창·키보드 버튼·범위 검사·가림·시나리오를 재사용한다. 숫자를 서버에 직접 전송하지 않는다. 촬영 모드에서는 정면 고정·회전 잠금, 로딩/WebGL 실패 메시지와 사진 전환을 지원한다. unmount 시 animation loop, controls, observer, geometry/material/texture/renderer를 해제한다. 뷰어는 lazy import하여 운영 화면에서 3D 모듈을 내려받지 않는다.

## 검증

- 모델 생성 `node frontend/scripts/build-cockpit.mjs`: 5290820-byte GLB 생성.
- `node frontend/node_modules/vite/bin/vite.js build frontend`: 성공. 3D lazy chunk가 500KB를 넘어 번들 크기 안내가 남는다.
- frontend `node --test tests/*.test.js`: 기존 44개 통과.
- Playwright `frontend/e2e/cockpit.spec.js`: GLB HTTP200/바이너리 magic, 실제 3D 숫자 클릭→편집창→359 입력→증가0, 노브 클릭, 사진 전환/상태 유지, 촬영 모드 검증. 로컬 시연 5175에 연결한 별도 임시 config로 실행한다.
- Chromium 데스크톱 스크린샷으로 패널 표시와 전환을 확인했다. 실제 태블릿 GPU/터치, 카메라 재촬영·OCR 정확도, 제조사 치수 일치는 미검증이다.

## 자체 리뷰와 인수인계

공유 상태를 재사용하며 backend 판정/관측 계약은 수정하지 않았다. 모델에는 외부 텍스처/원본 사진이 포함되지 않는다. PFD/ND·엔진 계기·조종간·좌석·센터 콘솔·창문·오버헤드는 개별 메시로 제공하며 주변 계기는 고정 모의 표시다. 사진/3D 전환과 시점 변경 시 Vision ROI를 다시 지정해야 한다. 외부 리뷰는 PR 제출 후 진행하며 자동 병합하지 않는다. 공개 사용법은 `frontend/README.md`에 기록했다. 로컬 5175 기본 페이지에서 확인 가능하다.

## 전체 조종석 메시 확장

사용자가 MCP에 한정되지 않는 조종석 메시를 요청하여 같은 WI/PR의 최종 범위를 확장했다.
`build-cockpit.mjs`는 창문 면/프레임, 바닥, side console, 두 좌석(쿠션·헤드레스트·벨트·레일),
조종간/러더 페달, 좌우 PFD/ND 및 중앙 엔진 화면, FMC 키패드, 스로틀 레버와 라디오,
오버헤드 토글을 실제 geometry로 생성한다. 원본 사진/외부 텍스처 없이 재생성 가능하다.
기존 MCP는 `mcp_root` 하위에 보존하고 전체/조종사/MCP 시점을 별도 카메라 프리셋으로 제공한다.
Raycaster는 불투명 형상 뒤의 조작부를 클릭하지 않도록 했다. 주변 계기는 고정 표시임을 UI에 명시한다.
Playwright는 GLB 내부의 좌석/바닥/중앙콘솔/창문/오버헤드/MCP 노드를 확인하고 세 시점 전환 후
기존 숫자 클릭·359→0·노브 증감·사진 전환·촬영 모드가 통과함을 확인했다.
전체와 조종석 시점 Chromium 렌더링에서 pageerror가 없고 메시를 스크린샷으로 확인했다.

## 실제 737-800 사진 기반 외형 개선

2026-10-23 사용자의 실제 사진 레퍼런스 요청으로 Cory W. Watts의 AA 737-800(2009),
Miami Air N734MA(2008) Commons 원본 사진을 검색하고 직접 비교했다. 링크는 frontend README에 기록했다.
사진은 임시 비교용으로만 내려받고 모델·텍스처·저장소에 포함하지 않았다.

- 형상: MCP를 얇게 줄이고 가로로 분산된 숫자 슬롯을 재배치했다. 양쪽 EFIS·COURSE/VS 창,
  스탠바이/기어 조작부, 하부 중앙 DU, 큰 U형 조종간/차트 클립, reverse/start 레버·trim wheel,
  각진 창문 구조물을 추가했다. 회색 주패널과 밝은 좌석 재질로 바꾸고 기본 시점을 눈높이 정면으로 바꿨다.
- 표시: Python/Pillow로 직접 그린 PFD/ND/엔진/FMC·메인패널·EFIS·MCP·오버헤드·체크리스트·직물·스로틀·무선 패널 PNG12개를 GLB BIN에 내장한다.
  원본 인식/서버 판정값을 쓰는 표시가 아니며 주변 화면은 고정 모의 표시다. MCP 숫자만 기존 React 상태에 연동한다.
- 검증: GLB의 헤더/자기완결 이미지/PNG 매직/버퍼 범위/정렬/텍스처 참조를 검사하는 단위 테스트를 추가했다.
  최종 frontend 단위45개와 MCP/시점/편집/가림 전환 E2E1개 및 빌드를 검증한다.
  화면으로 계기 상하 방향, 창문/센터 콘솔, 숫자 클릭을 확인했다. 그림자는 정적 생성 후 값 변경 때 갱신한다.
- 한계: 단일/복수 사진 기반 근사이며 실측 치수, 실제 비행계기 동작, 사진 수준 재질 일치 또는 태블릿 실장비 OCR 정확도를 보장하지 않는다.

## 사진 보기 전환 제거

사용자 요청으로 기본 화면의 사진 보기/3D 보기 전환을 제거하고 3D 조종석만 표시한다.
사용하지 않는 사진 렌더링 분기와 import/state를 제거했으며 오류 안내와 회귀 테스트를 현재 UI에 맞췄다.
기존 숫자 입력·증감·가림·촬영 모드는 유지한다.
