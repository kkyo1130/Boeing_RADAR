## 자동 영역 422 후속

사용자 보고 후 실행 로그에서 auto-calibration 422 반복을 확인했다. 개별 실패 응답 본문은 아직 미확보이므로 원인을 탐지 실패로 단정하지 않는다. 탐지 실패 자체도 422를 반환하던 구현을 수정해 `status=SEARCHING, token=null, rois=null`로 명시하고 이전 calibration을 제거한다. READY일 때만 인식을 시작하며 탐색 중 CAMERA DEGRADED를 보낸다. 프런트는 최대 8개 새 프레임으로 재시도하며 실패 시 입력 보류 안내를 유지한다. 카메라 전송 프레임은 1920×1080 안으로 비율을 유지해 축소한다. 형식 오류는 계속 422이며 프런트에서 FastAPI detail 메시지를 표시하되 원본 입력 이미지는 오류 문자열에 노출하지 않는다.

검증: demo 12개 테스트 통과(SEARCHING·이전 토큰 제거 포함), frontend69/빌드 통과(형식 오류 표시 수정 전). 서버 재시작, 실카메라 재확인은 사용자 입력 대기.

## 실제 실패 프레임 확보·표기 기반 탐색/OCR 보조

사용자가 웹캠 유지를 승인한 뒤 로컬 `.demo/vision-debug/latest.jpg` 한 장을 갱신해 실제 실패 프레임을 확보했다. 재현용 복사본 `.demo/vision-debug/repro.jpg`와 진단 결과는 Git 제외 경로에만 둔다. 수집용 환경변수는 런처에서 제거해 서버 재시작 이후 추가 진단 프레임 저장을 중단했다.

실제 이미지(1920×1080)에서 250/270/03000과 HDG/ALT 라벨을 확인했다. 색상 기반 검출은 HDG 대각선의 열 점유율 및 JPEG 재압축에 민감했고 1280 축소 영상에서는 실패했다. CNN v3도 실제 crop에서 OUT_OF_RANGE/LOW_MODEL_SCORE로 보류했다. 임계값만 완화해 CNN 값을 정상 처리하지 않았다.

- `vision/native/regions.swift`: Apple Vision으로 프레임 내 텍스트 및 정규화 좌표를 얻는다.
- `vision/text_windows.py`: 관측한 HDG/ALT 라벨 바로 아래의 유일한 3/5자리 숫자 span을 연결한다. 다중·누락·낮은 점수·범위 밖은 거부한다. 지시값·이전 값·고정 좌표는 사용하지 않는다. 색상 기반 탐색은 보조 fallback으로 유지한다.
- OCR v3가 읽지 못하면 ZIP과 동일한 Apple Vision OCR로 해당 crop을 읽고 원래 실패 사유와 source를 남긴다. 두 OCR의 유효한 값이 서로 다르면 OCR_ENGINE_DISAGREEMENT로 보류한다. 웹캠 UI에 Apple Vision 보조 인식 출처를 표시한다.
- 실제 확보 프레임의 1920 원본 및 1280/JPEG90 변형에서 HDG270·ALT03000과 ROI 반환 확인. TestClient의 실제 `/infer-frame` 호출은 HTTP200, 두 값 및 source=apple_vision_fallback, 약0.83초. 이 단일 프레임 결과를 전반적 정확도/실시간 장치 검증 완료로 확대하지 않는다.
- Vision API 테스트 60개 통과, frontend72/빌드 통과. 라벨 anchor가 IAS를 선택하지 않음, 변경 숫자에 좌표가 의존하지 않음, 누락·중복·범위 오류 보류 회귀 포함. 표시 박스의 실브라우저 시각 검증은 미실행.
