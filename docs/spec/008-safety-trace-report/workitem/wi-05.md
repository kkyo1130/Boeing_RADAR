# SPEC-008-WI-05 · Flight Safety Report와 PDF

2026-11-12 사용자 첨부 요청 범위. 상태 원본은 TODO. 현재 사용자 브랜치의 미커밋 구현이며 기존 다른 변경을 보존했다. 기존 WI 전체 또는 실제 장치 인수를 자동 완료 처리하지 않는다.

## 계획과 완료 조건

기존 V2Input/V2TraceEvent/Incident/V2Report를 재사용해 5개 섹션과 한글 PDF를 제공한다. 중복 사건·재전송·판독 불가·대체 지시를 거짓 해결로 집계하지 않는다. 종료 시 고정, 브라우저 소유권, AI 실패 대체, 다중 페이지/한글/실제 브라우저 다운로드를 검증한다. 모델/판정 로직 변경은 제외한다.

## 기존 구조 분석

- FastAPI+SQLAlchemy/SQLite, React+Vite. 기존 operations 화면이 POST /api/v2/flights로 세션을 만들고 v2 상태를 조회한다.
- ATC/Readback 구조화 결과와 전사는 V2Input.payload, 연관 지시는 V2Instruction, 수신/판정/경고/수정은 V2TraceEvent 및 V2FlightContext.state의 incidents/voice에 저장한다. 이미지/음성은 기존 evidence/media 경로로 연결하며 리포트가 재인식하지 않는다.
- 최종 비교·5초 설정 대기·복창 우선은 기존 validation_v2, 새 유효 관측으로 해결하는 것은 incidents_v2가 담당한다. voice claim과 재생 COMPLETED/실패/중단은 별도 기록이다.
- 기존 services/reports/v2.py가 종료 직전 판정과 원본 이벤트를 V2Report에 고정하고 ReportPanel이 작은 요약/JSON만 제공했다. 이 기능을 확장하며 병렬 리포트 DB/새 판정 엔진을 만들지 않았다.

## 구현 결과

- safety.py: 저장된 유효 ATC instruction/고유 occurrence/역사적 전체 일치 결과를 집계한다. 지시 건수와 사건 건수를 구분하고 미검증/대체를 해결로 세지 않는다. 이벤트별 원본 인식값·검증·그 시점 사건/경고 상태와 Correction Trace를 연결한다.
- reports/v2.py: 기존 응답 shape/summary/snapshot을 보존하면서 safety를 추가한다. 신규 종료 때 함께 저장하며 레거시 고정 리포트는 고정 데이터에서 읽기 전용 projection한다.
- summary.py: 선택적 AI 제공자에 실제 사실/이벤트를 보내고 정확한 사실 ID집합/digest 응답만 허용한다. 자유 생성 숫자/판정은 사용하지 않는다. 기본/실패는 규칙 요약이다. 자세한 프로토콜은 contracts/flight-safety-report.md.
- pdf.py: ReportLab+OFL NanumGothic 폰트 내장, 다중 페이지 한글/긴 원문/표/분류 그래프/상태색/로고/UTC/페이지 번호. 화면과 같은 safety 데이터로 생성하고 원문은 XML escape한다.
- access.py/operations_v2.py/receiving_v2: 신규 세션 브라우저에 HttpOnly capability, DB에는 hash만 보관한다. JSON/PDF/리포트 모두 동일 소유권 검사. 소유권 없는 옛 기록은 로컬 관리자 CLI 코드 발급→본문 교환 후 cookie. 기존 owner 재할당 거부.
- UI: 운항 종료 및 리포트 보기→확인 대화상자→/report?flight=ID. 요약 카드/페이지 단위 타임라인/분류 막대/수정 이력/AI 또는 규칙 요약, 상하단 PDF 버튼과 오류 메시지, JSON 링크. 기존 dark UI와 반응형 스타일 유지.
- DB: v2_report_owners(flight_id PK/FK, owner_hash indexed) 추가. 기존 테이블/데이터 변경 없음. 기존 migrate/create_all이 시작할 때 테이블을 생성한다. 입력/Trace/고정 리포트의 기존 트랜잭션은 유지한다.

## 실행·인수인계

프로젝트 루트에서 의존성을 설치한 다음 backend에서 실행한다. 기존 RADAR_DATABASE_URL을 쓰는 경우 같은 값을 유지한다. 이미 실행 중인 vision 서버와 충돌하지 않도록 별도 포트를 사용한다.

```sh
.venv/bin/python -m pip install -r backend/requirements.txt
cd backend
RADAR_V2_CONFIG=../contracts/examples/integration/config.json ../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

다른 터미널에서 프로젝트 루트 기준 `cd frontend && RADAR_API_TARGET=http://127.0.0.1:8002 npm run dev -- --port 5176`. 운영 화면 `http://localhost:5176/operations`에서 새 세션을 만들고 기존 실제 음성/카메라 생산자 경로로 입력한다. integration/config.json은 실행 예시 등록/정책이며 실제 운항 검증을 의미하지 않는다. 모델/생산자 활성화와 기존 데모 환경은 기존 실행 설정을 따른다.
운항 종료 및 리포트 보기→확인→리포트의 PDF 다운로드. 직접 경로 `/report?flight=<ID>`는 해당 브라우저 권한이 있어야 한다.
과거 소유권 없는 기록: backend 디렉터리에서 동일 RADAR_DATABASE_URL로 `../.venv/bin/python -m app.services.reports.access --flight <ID>`. 출력한 비밀을 해당 세션 페이지의 접근 코드 양식에 붙여넣는다. 임의 타 세션 owner 변경 기능은 없다.

### 제한·남은 확인

계정/조직 인증은 기존 시스템에 없어 브라우저 capability 권한만 추가했다. 운영 입력/state/evidence API 전체의 인증은 별도 범위이며 외부 공개 서비스 수준의 권한 체계를 구현했다고 주장하지 않는다. cookie를 잃은 이미 소유된 세션의 재할당도 자동 지원하지 않는다.
실제 입력이 저장되면 동일 경로로 집계하지만 이번 A-E는 synthetic fixture/모의 음성 완료를 사용했다. 새 실제 마이크·태블릿 카메라 E2E와 외부 AI 제공자 호출은 미실행이다. 화면을 사람이 보았거나 스피커 소리를 들었다는 기록은 미수집이다.
기본 AI는 규칙 요약이며 실제 제공자가 설정되어도 검증된 사실의 선택/순서만 AI에 허용한다. 안전 판정이나 오류 해결을 생성하지 않는다.
현재 사용자 브랜치의 기존 미커밋 변경과 섞이지 않게 파일 책임을 기록했으며 커밋/푸시/PR은 이번 실행에서 하지 않았다. 코드와 로컬 검증은 완료했고 공유 PR/실물 인수는 별도다.
