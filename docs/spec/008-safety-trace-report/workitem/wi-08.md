# SPEC-008-WI-08: 오류 사건 중심 타임라인

## 요청·기준·완료 조건

2026-11-17 사용자 요청: 긴 Error Timeline을 사건별 발생→경고→수정→해결 요약으로 바꾸고 반복 관측/전체 기록을 펼쳐보기로 옮긴다. 선행 로컬 `5db09f4`(기존 보고서 중복 집계와 YOLO 복구 포함)를 유지한다.

- 기본 화면은 occurrence별 한 타임라인/최대4단계다. 프레임 수나 정상↔보류 반복에 비례해 길어지지 않는다.
- 경고 재생 완료 증거와 수정 관측이 없으면 없음/확인 불가다. 미해결·대체·진행중을 해결로 바꾸지 않는다. 재발은 별도 사건이다.
- 원본 이벤트/수정 steps/최종 고정 레코드/집계는 보존한다. 상세는 화면에서 펼치고 JSON으로 내려받는다.
- PDF·인쇄도 사건 요약을 사용하고 전체 관측을 자동 확장하지 않는다.

## 구현

- `backend/app/services/reports/presentation.py`: 읽기 전용 `error_timeline` 투영 추가. 사건마다 탐지, 실제 완료 경고, 수정 관측 첫/마지막/횟수, 최종 상태4개를 생성한다. 원본 steps는 수정하지 않는다.
- `frontend/src/report-timeline.js`: 이전 서버/고정 자료에도 같은 요약을 계산하는 fallback. `ReportPanel.jsx`: 기본 오류 타임라인에 요약을 표시하고 전체 입력·검증/수정 상세는 닫힌 details로 제공한다. 상세 안의 기존 페이지 이동/그룹별 원본 관측 기능은 유지한다.
- `report.css`: 4단계 표시, 좁은 화면2열. 전체 로그를 펼친 상태에서도 인쇄 시 상세 로그를 제외한다. beforeprint도 전체 로그를 자동 열지 않는다.
- `backend/app/services/reports/pdf.py`: 반복 입력·검증 표와 반복 수정표 대신 사건별4단계 표. 원문은 화면/JSON에서 확인하도록 안내한다. 기존 보고서 소유권·동결·요약/분류는 유지한다.
- 계약 `contracts/flight-safety-report.md`: additive presentation 필드, 기본/상세/인쇄 규칙 갱신.
