검증 명령은 [통합 실행 안내](../../../../tests/integration/README.md)를 따른다. 이 환경에서는 기존 backend 가상환경 Python을 사용했다.

- 저장소 루트 `python -m pytest tests/integration -q --basetemp=<폐기 가능한 전용 임시 경로>`: **21 passed**. 서로 다른 임시 DB에서 두 번 성공했고 실행마다21개 실행 ID와 관측 ID가 서로 겹치지 않는 것을 로그로 확인했다. 실제 TCP HTTP·임시 SQLite·별도 uvicorn, backend 내부 monkeypatch/TestClient 없음.
- `backend/`에서 `python -m pytest -q`: **174 passed, 1 warning**. 경고는 기존 Starlette/httpx deprecation이다.
- 루트 `python contracts/check_v2.py`: **PASS, 6 JSON Schemas, 21 fixture expectations (Schema + DTO)**.

초기 실행은 샌드박스의 localhost bind 차단으로 실패했으며 로컬 서버 실행 권한으로 재실행했다. 최초 HTTP 실행에서 미래 관측의 processed_at도 미래여야 하는 DTO 제약과 지연 프레임이 이미 기록된 프레임과 다른 사례여야 하는 기대값을 바로잡았다. 제품 계약/구현을 완화하지 않았다. 통과 결과는 수정 후 실제 실행으로 확인했다.

미실행: 실제 카메라/마이크, Vision/통신 제품 어댑터, 외부 STT/OCR, 실측 정확도·지연·품질 보정, 다른 DB/Windows, 최종 숫자 비교·경고/Incident·리포트 E2E. 이 WI는 합의한 mock 생산자와 backend 계약 통합을 검증하며 SPEC-003/004/005 이후 기능 완료를 뜻하지 않는다. `fixture-audio-*`는 mock 참조 문자열이고 실제 녹음 파일이 아니다. v2 state의 최종 결과는 계속 UNVERIFIED다.
