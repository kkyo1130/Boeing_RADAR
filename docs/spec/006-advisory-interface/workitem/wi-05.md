## 구현

`Pilot.jsx`는 URL의 명시적 flight ID에 연결하고 기존 `useFlight`의 snapshot 검증·revision 순서·1초 조회·4초 응답 제한·서버 재검증을 재사용한다. 운영 화면은 이 hook을 export하고 현재 비행의 링크를 제공한다. `main.jsx`에서 `/pilot`만 분기하며 기존 MCP와 운영 화면을 유지한다.

서버의 readback/setting 항목 판정에서 NORMAL을 제외한 항목을 단계별로 표시한다. 수치 비교로 판정을 만들지 않는다. MISMATCH는 항목·출처·단위가 붙은 두 값, UNVERIFIED는 짧은 사유와 확인 불가/설정 변경 대기로 표시한다. HDG0은 유효 값이다. 불일치를 먼저 배치하고 다른 오류/보류도 함께 유지한다. 장치의 끊김·품질 저하·상태 미상을 별도로 표시한다.

전체 일치는 서버 NORMAL·표시할 비정상 항목 없음·장치 비가용 없음일 때만 표시한다. 연결 실패와 종료에서는 이전 값·현재 일치/불일치를 모두 숨긴다. URL에 비행 ID를 보존하며 다른 운영 탭의 비행 선택으로 조종사 화면을 조용히 바꾸지 않는다. 수동 ID 연결과 재연결을 지원한다. 상세 근거/음성/시작·종료는 운영 화면에 있다. 이 화면은 음성을 추가 재생하지 않는다.

`pilot.css`는 큰 글씨·어두운 배경·문구와 색상 구분·반응형 배치를 제공한다. 높이가 짧은 가로 화면에는 간격을 줄인다. 많은 항목은 숨기지 않고 문서 흐름에 유지하므로 화면보다 많으면 세로 스크롤이 필요하다.

## PR #20 리뷰 수정 · 2026-11-09

리뷰 대상 `6c60376`, P2 [전체 판단 보류 사유 누락](https://github.com/kkyo1130/Boeing_RADAR/pull/20#discussion_r4512177110)을 수정했다. 서버는 새 ATC 미채택 시 전체 UNVERIFIED/LATEST_ATC_NOT_ADOPTED와 이전 항목 판정을 함께 반환한다. 기존 UI는 남아 있는 오류 카드가 있으면 전체 보류 사유를 표시하지 않았다.

`Pilot.jsx`에서 전체 보류 여부·사유를 카드 유무와 독립적으로 처리한다. 상단에 `판단 보류 · 새 관제 지시 확인 대기`를 표시하면서 기존 오류 카드·출처·비교값을 유지한다. 알려지지 않은 사유는 `새 입력으로 재확인 필요`로 표시하며 연결 상실·종료 시 과거 보류 문구도 숨긴다. 서버 판정이나 숫자 비교 로직은 바꾸지 않는다.

회귀: 전체 보류+기존 오류, 카드 없는 보류, 미지 사유, 연결 상실/종료, 최초 null snapshot을 실제 JSX 렌더링으로 확인한다. 브라우저는 세 크기에서 새 ATC 보류 전환→보류 안내와 기존 두 비교값이 viewport 안에 공존→보류 해제 시 문구 제거를 추가 검사한다. 초기 검증에서 null snapshot 접근 오류를 발견해 optional chaining과 초기 렌더 회귀로 수정했다.

최종 검증은 frontend `npm test` 53개 통과, `npm run build` 통과, Chrome `npx playwright test --config playwright.pilot.config.js` 4개 통과, `git diff --check` 통과다. 브라우저는 API fixture이고 실장비/실서버 검증은 미실행이다. 자체 재검토로 전체 보류와 유지된 오류의 동시 표시를 확인했으며 수정 head에 대한 외부 재리뷰 완료/승인을 주장하지 않는다. 기존 PR에 후속 커밋으로 제출하고 TODO reviewing을 유지한다.

## 2026-11-11 실제 복창 성공 표시 보완

기준 dev `0e80cb4`, 브랜치 `codex/pilot-readback-result`. 사용자가 실제 ATC·Pilot 발화 시험에서 운영 화면의 복창 일치와 Pilot의 보류 표시가 모순처럼 보인다고 보고했다. 실제 서버는 READBACK=NORMAL, SETTING=UNVERIFIED/INPUT_NOT_AVAILABLE였다. Pilot은 비정상 필드만 표시해서 정상 복창 결과가 전부 사라지고 카메라 입력 대기만 남았다. 또한 이전 안내의 빈 비행과 실제 녹음을 진행한 새 비행이 달랐으므로 운영 화면의 링크로 동일 비행 Pilot을 열었다.

- 구현: `Pilot.jsx`에 서버가 확정한 복창의 항목·값을 보여주는 `Readback matched` 영역을 추가했다. 단계가 SETTING/MONITORING이고 복창 전체 및 각 필드가 NORMAL이며 값이 있을 때만 표시한다. 연결 종료·비행 종료·새 ATC 대기·새 복창 보류·음성 장치 장애에는 과거 성공을 숨긴다. MCP 입력 누락은 `Awaiting camera input`, 전체 보류 사유는 `MCP setting not verified`로 표시한다. 수치 비교·서버 판정·STT 모델은 변경하지 않는다.
- 레이아웃: `pilot.css`의 독립된 녹색 복창 요약과 기존 MCP 보류 카드를 함께 표시한다. 복창 성공을 전체 NORMAL로 승격하지 않는다.
- 검증: Node24 `npm --prefix frontend test` **62 passed**, `npm --prefix frontend run build` 성공, 설치된 Chromium으로 `npm --prefix frontend run test:e2e -- e2e/pilot.spec.js` **5 passed**. 새 테스트는 카메라 없는 복창 성공의 표시, HDG0 보존, 새 관제에서 남아 있는 NORMAL 필드의 성공 표시 제거, 연결·비행·음성 장치 상태를 검사한다. 3D 번들 크기 안내는 기존대로 남는다.
