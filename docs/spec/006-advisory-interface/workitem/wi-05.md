## 구현

`Pilot.jsx`는 URL의 명시적 flight ID에 연결하고 기존 `useFlight`의 snapshot 검증·revision 순서·1초 조회·4초 응답 제한·서버 재검증을 재사용한다. 운영 화면은 이 hook을 export하고 현재 비행의 링크를 제공한다. `main.jsx`에서 `/pilot`만 분기하며 기존 MCP와 운영 화면을 유지한다.

서버의 readback/setting 항목 판정에서 NORMAL을 제외한 항목을 단계별로 표시한다. 수치 비교로 판정을 만들지 않는다. MISMATCH는 항목·출처·단위가 붙은 두 값, UNVERIFIED는 짧은 사유와 확인 불가/설정 변경 대기로 표시한다. HDG0은 유효 값이다. 불일치를 먼저 배치하고 다른 오류/보류도 함께 유지한다. 장치의 끊김·품질 저하·상태 미상을 별도로 표시한다.

전체 일치는 서버 NORMAL·표시할 비정상 항목 없음·장치 비가용 없음일 때만 표시한다. 연결 실패와 종료에서는 이전 값·현재 일치/불일치를 모두 숨긴다. URL에 비행 ID를 보존하며 다른 운영 탭의 비행 선택으로 조종사 화면을 조용히 바꾸지 않는다. 수동 ID 연결과 재연결을 지원한다. 상세 근거/음성/시작·종료는 운영 화면에 있다. 이 화면은 음성을 추가 재생하지 않는다.

`pilot.css`는 큰 글씨·어두운 배경·문구와 색상 구분·반응형 배치를 제공한다. 높이가 짧은 가로 화면에는 간격을 줄인다. 많은 항목은 숨기지 않고 문서 흐름에 유지하므로 화면보다 많으면 세로 스크롤이 필요하다.

## 검증

- frontend `npm test`: 49개 통과. 새 Pilot 실제 JSX 렌더링 5개 포함. 혼합 오류/출처/HDG0, stale/null, 변경 대기, 연결 상실/종료, 전체 정상과 장치 비가용을 확인.
- frontend `npm run build`: 통과.
- frontend `RADAR_CHROMIUM_PATH=<installed Chrome> npx playwright test --config playwright.pilot.config.js`: API fixture 브라우저 4개. 480×320, 800×480, 360×640에서 단일 오류 비교값의 viewport 포함·가로 넘침 없음, 복명복창/MCP 오류 공존, stale→값 숨김, 연결 상실→판정 숨김, 재연결·새로고침 복구 및 ID 수동 연결.
- 브라우저 캡처에서 최초 480×320 레이아웃의 값이 아래로 밀리는 것을 확인해 짧은 화면용 CSS와 `toBeInViewport` 회귀를 추가했다.
- Node25.8.1 환경은 package engines의 지원 범위 밖이다. `npm ci --engine-strict=false`로 설치했고 테스트/빌드 결과는 이 환경에서의 결과다. 처음 일반 권한의 npm 네트워크/로컬 서버 실행이 실패하여 허용된 실행 권한으로 재시도했다. Playwright 기본 브라우저가 없어 설치된 Chrome을 사용했다. SSR 시험에서 기존 Vite 의존성 scan 종료 경고가 있었지만 실패 테스트는 없었다.
- 실제 backend HTTP/실카메라·마이크·태블릿 장착·거리별 가독성·다른 브라우저는 미실행. 브라우저 검증은 서버 응답 fixture이며 실장비 성공을 뜻하지 않는다.
