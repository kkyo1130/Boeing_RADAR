### 처리 순서

START 호출부호 검사 → 상태 표시 → 입력 제어 → END → 리포트 이동.

현재 저장소의 기존 모듈을 먼저 확장한다. 위 수정 영역 중 아직 없는 경로는 생성 후보이며 기존 구현이라고 표시하지 않는다. 입력·출력 경계에서 실패 사유와 ID를 보존하고 성공과 미실행을 구분한다.

## 시작 전 호출부호 입력

상위 스펙 v5와 D-004-18·D-004-23에 따라 사용자가 비행 시작 전에 대상 호출부호를 입력한다. 입력값은 시작한 세션에 연결해 표시하고 세션 중 변경하지 않는다. 빈 값이나 미등록 호출부호이면 START를 완료하지 않는다. 미등록인 경우 등록된 호출부호를 안내하고, 개발자가 설정에 추가·검증하기 전까지 해당 입력을 임시 허용하지 않는다. 입력 형식·정규화·API 필드는 SPEC-002에서 확정한다. D-004-22에 따라 허용 표현은 개발자 설정 파일을 사용하며 이 화면에는 허용 표현 추가·수정 기능을 두지 않는다.

##### 구현

**동작:** 기존 `/` 태블릿 모의 MCP를 유지하고 별도 `/operations`에 서버 운영 화면을 추가했다. 등록 호출부호로 START하여 server flight ID/호출부호를 고정하고 항목별 지시 출처·복명복창·카메라 선택값·오류 단계·판단 보류·장치 상태·발생 기록을 표시한다. END는 서버가 종료한 것을 전체 snapshot으로 다시 확인한 뒤 종료 기록 화면으로 전환한다. 완성 리포트는 SPEC-008 범위이므로 없는 리포트 화면으로 이동한 것처럼 만들지 않았다.

**서버 소유 판정:** UI는 숫자 비교로 NORMAL/MISMATCH/RESOLVED를 생성하지 않는다. state.validation의 필드별 expected/actual/result/reason과 해당 지시/관측 ID·UTC를 표시한다. ALT는 feet 그대로, HDG0은 유효 숫자이고 null은 확인 불가다. 서버가 부분 ALT 지시를 채택하면 ALT 새 출처와 기존 HDG 출처·오류/발생 건을 함께 표시한다. 기존 완료 메타데이터를 쓰거나 초기화하지 않는다.

**세션/통신:** 빈 호출부호 START는 로컬 차단하고 미등록 값은 서버422/등록 목록을 표시한다. 시작 후 호출부호 편집은 없다. 브라우저에는 flight ID만 저장하며 전체 상태·정상 배지는 저장하지 않는다. 새로고침·다시 연결은 전체 state를 다시 조회한다. 저장소가 비가용이어도 현재 탭은 동작한다. 기존 비행 ID로 수동 연결할 수 있고 `비행 선택으로`는 로컬 선택만 해제한다.

조회 완료 후1초마다 다음 GET을 예약하고4초 응답 제한을 적용한다. 실패 시 이전 숫자는 마지막 기록으로 구분하고 모든 현재 판정 배지는 보류로 전환하며 END를 비활성화한다. 낮은 revision·다른 비행·뒤늦은 요청은 적용하지 않고, 같은 revision에서 서버의 최신성/시간 판정이 달라진 경우는 반영한다. 화면 전환/재연결 시 이전 요청을 취소하고 폐기한다. START/END는 중복 클릭을 막고 쓰기 요청을 자동 반복하지 않는다.

**시간 경과와 이력:** GET이 ADJUSTMENT_DEADLINE_MISMATCH를 반환하면 비행/지시/wait_until별 POST revalidate로 서버 판정·발생 건을 저장한다. 브라우저의 시계로 대기 종료/수치 불일치를 만들지 않는다. 성공한 같은 대기는 현재 연결 동안 중복 저장하지 않으며, 재접속 후 명령이 반복되어도 서버 발생 건의 멱등 정책을 따른다. 종료 필드는 현재 정상으로 표시하지 않고 `종료 기록`으로 표시한다.
