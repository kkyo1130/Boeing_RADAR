### 처리 순서

현재 목표 확인 → 기존 발생 건 조회 → 새 관측 검사 → 해결/대체 저장.

현재 저장소의 기존 모듈을 먼저 확장한다. 위 수정 영역 중 아직 없는 경로는 생성 후보이며 기존 구현이라고 표시하지 않는다. 입력·출력 경계에서 실패 사유와 ID를 보존하고 성공과 미실행을 구분한다.

##### 구현

오류를 `flight_id + instruction_id + stage + field + occurrence_id`에 연결했다. 같은 미해결 오류의 새 관측은 같은 OPEN을 갱신하고 최초 탐지·첫 판정/근거를 보존한다. 새 유효 관측으로 해결한 RESOLVED, 검증된 새 목표가 대체한 SUPERSEDED, 미해결 비행 종료 ENDED_UNRESOLVED를 분리했다. 해결 후 재발은 새 occurrence다. legacy ClearanceStatus/VERIFIED/RESOLVED 계약과 섞지 않는다.

| backend/app/services/receiving_v2.py | 기존 수신·Pilot 구간 등록/취소·종료 트랜잭션에서 reconcile 및 INCIDENT_UPDATED 원자 저장, 원본 frame/segment/attempt/근거 보존 |

해결에는 현재 필드 NORMAL뿐 아니라 다른 observation_id, 다른 frame_id/segment_id, 마지막 오류 관측보다 뒤인 원본 observed_at이 필요하다. 수신 적격성(품질/최신성/지시 revision/구간·attempt/규칙/채널)을 우회하지 않는다. 이전 프레임에 새 ID를 붙이면 SOURCE_SAMPLE_REUSED로 배제한다. 판독 불가·낮은 품질·장치 끊김/복구·stale은 현재 확인을 보류하고 기존 오류를 해결하지 않는다.

복창 수정은 해당 지시가 현재 소유하는 필수 항목과 호출부호 전체를 새 발화로 확인한다. 일부 정상만으로 불완전한 수정 발화를 해결하지 않는다. 설정은 필드별 해결하여 다른 오류를 지우지 않는다. 부분 ALT 새 지시는 ALT의 옛 발생 건만 SUPERSEDED로 닫고 HDG 출처·오류·음성 완료 메타데이터를 유지한다. 새 ATC 등록/해석 실패/대상 외 교신은 대체가 아니다.

저장소는 기존 V2FlightContext.state JSON이며 기존 DB 컬럼/migration은 변경하지 않았다. 각 발생 건은 최초/최신/마지막 오류/해결 근거와 판정·탐지/재관측/재검증/해결/종료 UTC를 가진다. actual MCP 조작 시각은 관측하지 않으므로 추정해 채우지 않는다. notified_at/voice_completed_at은 후속 알림용 nullable 메타데이터이며 실제 출력 전 null이다. 이 WI는 음성·화면 출력을 실행하지 않는다.

GET state는 읽기 전용이다. 시간 경과에 따라 validation/current_check가 달라져도 발생 건/Trace를 새로 저장하지 않는다. 소비자는 최초5초 대기 만료 wait_until에 맞춰 POST revalidate 또는 새 입력을 보내 영속화해야 한다. 백그라운드 자동 작업은 없다. POST revalidate는 관측/값/해결 상태를 본문으로 받지 않으며 종료 비행409다. 반복 POST는 REVALIDATED 명령 Trace를 남기되 같은 오류 발생 건을 복제하지 않는다.
