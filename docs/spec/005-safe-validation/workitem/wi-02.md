**처리 순서:** 기존 수신의 버전/문맥/규칙·품질·시간 적격성을 보존한다. 유효한 복창 숫자/호출부호를 항목별 목표와 비교하고 최초 모두 일치한 서버 시각 t0를 지시별로 기록한다. 설정 차이는 t0+5초 전에는 expected/actual을 보존하며 UNVERIFIED/INITIAL_ADJUSTMENT_WAIT로 보류한다. 정확5초부터 최신·유효한 차이는 MISMATCH다. 시간만 지나거나 null/stale이면 오류로 만들지 않는다.

해당 지시가 소유한 설정 필드 전부가 유효·일치하면5초 전에도 조기 일치로 전환한다. 일부 일치만으로 완료 기억을 만들지 않는다. 완료 후 같은 목표의 새 유효 값이 달라지면 추가 대기 없이 SETTING_DEVIATED_AFTER_MATCH로 후보가 된다. 같은 관측 재송신이나 같은 지시의 복창 재확인으로 최초 타이머를 재시작하지 않는다.

ALT B/4000만 바뀌면 ALT의 B 복창/타이머와 HDG A/270의 기존 소유권·확인/감시를 분리한다. B에 HDG 재복창을 요구하지 않는다. 새 ATC 미채택/최신 복창 보류 중에는 과거 필드 정보는 유지하되 기존 안내 후보를 비우고 새 복창을 기다린다. B 복창 일치 후 ALT가 기다리는 동안 기존 HDG 재불일치를 숨기지 않는다.

**저장·실패·호환:** validation_memory와 validation_snapshot은 기존 v2 JSON state를 사용한다. 입력·판정·t0/완료 기억·INPUT_RECEIVED Trace를 같은 트랜잭션으로 저장하고 실패 시 모두 rollback한다. 새 DB 컬럼/migration은 없다. GET은 사본에서 기한/만료를 평가하며 revision/DB/Trace를 쓰지 않는다. current의 과거 수신 shape/result는 호환용이며 최종 비교는 validation이다. 기존 v1 VERIFIED/RESOLVED·DTO·Trace는 유지한다.

명확한 다른 등록 호출부호는 CALLSIGN MISMATCH로 구분하고, 호출부호 누락/미상/저품질/규칙 충돌은 보류한다. 확인 전 READBACK과 현재 Cockpit은 freshness를 검사한다. 유효할 때 완료한 복창은 같은 지시·관측·값의 완료 근거로 유지해 새 카메라로 지속 감시한다. 새 복창 시도/취소/health로 현재 문맥이 바뀌면 이전 근거를 재사용하지 않는다. 구조 근거/소유권이 없는 기존 비행 기록도 새 입력 없이 정상으로 승격하지 않는다.

**범위:** 안내 후보 데이터까지만 구현했다. 실제 UI 갱신/푸시·교신 우선 음성 재생·반복 억제·Incident 생성/해결·리포트·실장비/모델 성능은 후속 WI 범위다. query 때 결과가 바뀌는 타이머이며 백그라운드 재생 작업을 만들지 않는다.

##### 리뷰

단일 세션에서 구현과 별도로 보류를 오류/정상으로 승격하는 위험, 단계 우선순위, 부분 지시 출처, 새 시도/취소/health, 기한/중복·동시성·원자성을 대조했다. 수행하지 않은 사람/별도 에이전트 리뷰를 주장하지 않는다.

- 최신 ATC가 아직 미채택이거나 새 복창이 불명확하면 기존 targets/current가 남아 있어도 과거 NORMAL·안내를 재사용하지 않도록 확인했다.
- 새 ALT 타이머가 기존 HDG 오류를 덮지 않도록 지시별 t0와 필드별 완료 ID를 분리했다. 새 복창 대기 중 안내 억제와 B 복창 뒤 기존 HDG 오류 재노출을 각각 회귀로 검증했다.
- 단계 aggregate는 확인 가능한 MISMATCH와 다른 필드 UNVERIFIED를 함께 보존한다. 초기 설정 대기만으로 MISMATCH를 만들거나 일부 일치를 전체 완료로 latch하지 않게 했다.
- state의 최근 전역 구조 PASS 대신 수신 시 해당 필드에 붙인 지시/규칙 근거를 사용해 부분 지시 후 오래된 PASS 재사용을 막았다. 호출부호 근거도 지시/시도별로 비운다.
- GET에서 타이머/상태를 쓰지 않으며 실제 입력 commit 실패가 t0만 남기지 않는 것을 회귀로 확인했다.

선행 PR #8의 외부 리뷰 P2는23a902c에서 수정·검증하고 미해결 스레드0·최신 head 확인 후525f98a로 병합했다. 상세 원문/수정/결과는 [WI-01 리뷰](wi-01.md#리뷰)에 기록했다. 이 WI의 새 PR 외부 리뷰는 제출 후 진행하며 자체 검토/테스트를 자동 리뷰 완료나 APPROVED로 표현하지 않는다.

##### 인수인계

전용 브랜치 `codex/spec-005-wi-02-three-state-validation`의 커밋/PR을 dev에 제출한다. 원본 다른 변경은 보존하고 이 파일의 기존 네 결과 항목을 실제 기록으로 채웠다. [실행 계약](../../../../contracts/validation-v2.md), 공개 Schema·DTO, [HTTP 실행 안내](../../../../tests/integration/README.md)가 재현 원본이다.

새 v2 비행을 시작하고 ATC/Pilot 구간→관측을 등록한 뒤 state.validation의 observation/instruction ID·예상/실제·사유와 INPUT_RECEIVED Trace를 대조한다. 규칙/품질/freshness 정책은 기존 설정 snapshot을 사용한다.5초는 사용자 시연 결정이며 검증된 운항 기준이 아니다. 반복 실행은 별도 폐기 가능한 임시 경로/실행 ID로 분리한다.

다음 SPEC-005-WI-03은 혼합 오류·보류·규칙·부분 지시·정확 경계·API·새 입력의 전체 회귀/거짓 정상 검증을 확장한다. SPEC-006은 phase/대표 단계·advisory_candidates를 조회/구독해 화면·교신 우선 재생과 실제 완료 기록을 연결한다. SPEC-007은 별도 Incident/해결과 새 관측 조건을 연결한다. 후보 생성은 실제 재생이 아니며 NORMAL은 Incident RESOLVED가 아니다.

구형 current에 새 소유권/규칙 근거가 없거나 확인 전 복창/현재 카메라가 만료되면 보류한다. 같은 지시의 복창 완료 근거는 유지하되 현재 카메라나 새 시도의 누락을 대신하지 않는다. 사용자 후속 지시 없이 다음 PR을 자동 병합하거나 전체 작업 목록을 자동 구현하지 않는다.
