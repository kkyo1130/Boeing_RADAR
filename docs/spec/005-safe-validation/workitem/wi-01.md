## 구현

### 목적·입력·출력

모델의 구조화 결과와 같은 원문 transcript를 규칙 코드로 재대조한다. HDG0~359, 명시 FL 형식과 feet 변환, 등록 호출부호, 부분 범위, 구간/시도/시각 순서, 명시 상한·목표 급변 정책을 검사해 PASS/INVALID/NEEDS_REVIEW 및 검사별 근거를 반환한다. 같은 AI에 재질문하거나 다른 모델의 동의를 독립 검사로 표현하지 않는다.

입력은 v2 DTO를 통과한 ATC/READBACK dict와 서버 등록 문맥, 이전 ALT/HDG 목표 및 비행 시작 때 고정한 `StructurePolicy`다. 출력은 공개 `StructureResult`로 원본 observation/flight/segment/attempt ID, rules_version, policy_ref, 원문 유도값과 검사 사유를 보존한다. 호출 함수는 원본 dict·문맥을 수정하지 않는다.

### 처리 순서와 보류·저장

1. 기존 수신 서비스가 URL/body 비행·활성 세션·중복·등록 구간/최신 시도·취소·ATC 채택 여부를 검사한다. 이 단계에서 배제한 입력의 규칙 결과를 다른 입력에서 빌리지 않는다.
2. 서버에 고정한 호출부호·구간·규칙 정책과 원문을 규칙 서비스에 전달한다. 모델의 instruction_check와 서버의 규칙 결과는 별개다.
3. 등록 ID/역할·수음 시작/끝·처리 시각, 등록 호출부호의 원문 prefix/메타데이터를 확인한다. 원문 전체를 지원 문법으로 해석하며 조건문·지원하지 않는 꼬리 명령을 버리지 않는다.
4. 명시 FL은 정확3자리→feet로 유도한다. fields의 숫자/단위·raw_text·원문 명시 항목 집합을 대조하고360→0, null→0, 임의 단위 변환·숫자 수정을 하지 않는다.
5. 필요한 정책 미설정은 NEEDS_REVIEW, 명시 상한 초과는 INVALID다. 새 ATC의 이전 지시 대비 급변은 경계 초과 시 NEEDS_REVIEW다. 방위 차이는 짧은 원주 거리를 사용한다. 실제 항공기 속도/상승률을 추정하지 않는다.
6. INVALID가 하나라도 있으면 INVALID, 그 외 NEEDS_REVIEW가 있으면 NEEDS_REVIEW다. 비PASS이면 목표·현재 숫자 적용을 보류한다. 서버 PASS도 모델 실패·품질·freshness·장애 보류를 해제하지 않는다.
7. 원본 payload·상태·해당 관측의 규칙 결과/정책·Trace를 기존 트랜잭션으로 저장한다. commit 실패는 함께 rollback된다. 중복 재전송은 기존 receipt/event_id를 유지한다.

`GET .../state.structure_checks`는 ATC/READBACK별 최근 **실제 검사**다. 결과의 관측 ID를 확인해야 하며, 새 시도/health 때문에 현재값이 사라졌다고 이 역사 결과를 최신 정상 근거로 쓰면 안 된다. Trace의 structure_check는 해당 input에 수행했을 때만 존재한다. ATC 채택을 기다리던 Pilot은 같은 문맥으로 재검사하고 DEFERRED_READBACK_RECHECKED 이벤트에 자신의 결과를 기록한다.

DB 컬럼·새 migration은 추가하지 않았다. 기존 context JSON/Trace를 사용한다. 기존 v2 비행에 정책 snapshot이 없으면 필요한 검사에 NEEDS_REVIEW를 반환하며 임의 기본값을 넣지 않는다. v1 DTO·라우터·비교·Trace는 보존한다.

### 지원 범위와 기술 결정

지원 English 문형·ASCII/자리별 발음·명시 FL/feet·부분 항목·문장 길이 경계는 [실행 계약](../../../../contracts/structure-rules.md)을 따른다. 임의 음성 표현 전체를 지원한다고 주장하지 않는다. 상한50000ft·급변10000ft/180도는 `synthetic-contract-tests/1`의 합성 정책으로 회귀와 경계를 재현하기 위한 값이다. 실장비·운항 기준으로 확정하지 않는다. 미설정/null의 보류 경로도 별도로 검증했다.

최종 NORMAL/MISMATCH/UNVERIFIED 비교, 복창/설정 대표 오류, 5초 대기·조기 설정 일치·이후 감시·알림·Incident·리포트는 이번 구현에 포함하지 않는다. v2 전체 결과는 계속 UNVERIFIED다.

## 인수인계

### 산출물·재현 방법

브랜치 `codex/spec-005-wi-01-structure-rules`의 구현 커밋 `7a4a1b8a52b84e3223035f8b6489e7cc206b4e86`를 [PR #8](https://github.com/kkyo1130/Boeing_RADAR/pull/8)로 dev에 제출했다. 이 문서의 게시 결과 기록은 같은 WI의 후속 문서 커밋이다. 원래 작업 디렉터리의 다른 미커밋 변경은 보존했다. 실행·설정·공개 Schema의 원본은 위 파일 표와 [규칙 계약](../../../../contracts/structure-rules.md), HTTP 실행은 [통합 README](../../../../tests/integration/README.md)를 따른다.

1. backend 의존성을 설치하고 예제 설정을 복사한다. 실측 근거 없이 합성 정책을 운용 기준으로 복사하지 않는다. 기준이 없으면 null 보류로 재현한다.
2. 설정 파일을 RADAR_V2_CONFIG로 지정하고 새 v2 비행을 시작한다. 정책 변경은 새 비행에만 반영된다.
3. 등록 ATC/Pilot 구간을 먼저 전송하고 같은 ID의 관측을 보낸다. state.structure_checks와 INPUT_RECEIVED/DEFERRED_READBACK_RECHECKED의 structure_check를 observation ID로 대조한다.
4. 실제 모델/장비를 연결할 때는 지원 문형 밖의 결과가 NEEDS_REVIEW가 되는 경로와 원문 참조·freshness/품질 검사를 따로 인수한다.

### 다음 WI-02 연결점·남은 작업

- 기존 v2 `targets`, `readback_required`, `current`, `channels`와 관측에 연결된 규칙 결과를 사용해 필드별 NORMAL/MISMATCH/UNVERIFIED를 계산한다. 정책 PASS만으로 전체 정상/해결을 만들지 않는다.
- 확인 가능한 복창 불일치를 우선하면서 Cockpit 판독 불가와 다른 항목의 보류/오류도 보존한다. 구조 규칙 미통과·stale·품질 부족·장애는 수치 불일치로 단정하지 않는다.
- 복창 일치 시점부터 최초5초 대기, 대기 중 전부 일치하면 조기 일치, 이후 지시값 이탈 즉시 재확인, 부분 ALT 변경 시 기존 HDG270의 출처·감시 유지 등 사용자 결정을 적용한다. 중복 복창으로 타이머를 재시작하지 않는다.
- 새 ATC가 아직 처리 중이거나 규칙 보류로 미채택이면 이전 targets가 남아 있다는 이유로 새 지시를 정상 완료로 표시하지 않는다. 최신 ATC 입력·미채택 상태와 적용된 지시를 함께 구분한다.
- state의 최근 구조 결과는 역사 정보일 수 있다. 반드시 현재 instruction/attempt/observation과 맞는지 확인하고 오래된 PASS를 최신 입력으로 재사용하지 않는다.
- 규칙 문형을 확대하거나 실제 상한/급변 정책을 확정할 때는 근거/버전·정상/실패 fixture와 공개 Schema 호환을 함께 갱신한다.

다음 행동은 이 WI PR 외부 리뷰다. 병합·후속 WI는 사용자의 이후 실행 범위에 따라 진행하며 전체 작업 목록을 자동 구현하지 않는다.
