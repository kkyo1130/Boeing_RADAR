##### 리뷰

단일 세션에서 계획·구현·검증·리뷰 역할을 순서대로 수행했다. 별도 에이전트/사람의 검토를 주장하지 않는다.

- 제품 내부 aggregate 함수를 oracle로 부르지 않고 인수 표의 기대 결과를 별도로 선언했다. 코드와 같은 결과를 재계산하는 것만으로 통과시키지 않는다.
- 조합 표의 입력이 수신 적격성 이후 상태라는 가정을 적고, 실제 API·HTTP에서 품질·시각·문맥·원문·원본 저장을 별도로 대조했다.
- MISMATCH와 다른 필드의 UNVERIFIED를 동시에 확인하며 현재값 만료/새 장애와 오래된 지연 샘플 배제를 구분했다. 이미 확인한 같은 지시의 복창 근거와 새 관측의 적격성을 혼동하지 않는다.
- 불일치 fixture의 raw_text·숫자를 일치시키고, 요청 원본/접수 event_id·관측/지시 ID·Trace를 함께 검사했다. 상태만 맞고 원본 근거가 다른 경우도 검출한다.
- 제품 코드·정책·Schema를 바꾸지 않은 것을 diff로 확인하고, 모든 기존 v1/v2 계약·migration·원자성·취소/순서 회귀를 재실행했다.

선행 PR #9는 자동 리뷰 완료 head7423d24의 P2 1건(상태 endpoint 표의 고정 UNVERIFIED)을7066a08에서 수정했다. 문서 대조·스레드 해결·최신 head/병합 가능 상태·체크0 확인 후b3262cf로 squash merge했다. 자세한 원문/근거는 [WI-02 리뷰](wi-02.md#리뷰)에 기록했다. 수정 head의 별도 자동 재리뷰/APPROVED가 있었다고 쓰지 않는다.

이 WI의 새 PR 외부 리뷰는 제출 후 진행한다. 자체 검토와393/37 테스트 통과를 외부 승인으로 바꾸어 기록하지 않는다. 실제 지적이 있으면 이 WI 브랜치에서 수정하고 근거를 갱신한다.
