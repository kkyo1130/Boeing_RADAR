# PR #22 취소 후 새로고침 리뷰 수정

SPEC-004-WI-02의 PR #22 리뷰(PRRT_kwDOU6uHq861UiPE)는 새 관제 녹음을 취소하고 페이지를 다시 열면 이전 지시의 복창 버튼이 활성화되는 문제를 지적했다. React 상태에만 있던 입력 시도를 비행별 브라우저 localStorage에 저장하도록 수정했다. 마이크/등록 시나리오를 시작하기 전에 pending을 기록하며, 새 서버 응답의 ATC ID를 저장하고 현재 채택 ID와 같을 때에만 복창을 허용한다. 같은 origin의 탭에는 storage 이벤트로 동기화한다.

저장소를 사용할 수 없으면 입력 시작을 거부하고 복창도 보류한다. 이 보호는 같은 브라우저/origin의 데모를 위한 것으로 서버 전역의 미제출 녹음 상태를 만드는 기능은 아니다. 별도 브라우저/API 클라이언트나 사용자의 사이트 데이터 삭제까지 보호한다고 주장하지 않는다. 서버에 제출된 새 ATC의 실패 처리는 기존 서버 정책을 유지한다.

기준은 PR #22 head da0f219이며 별도 worktree에서 수정했다. frontend Node24에서 단위55개, 빌드, Playwright speech-modes 1개가 통과했다. 브라우저 테스트는 서버 응답을 조작하지 않고 취소→실제 reload→복창 비활성→새 ATC 채택→복창 활성 순서를 검증한다. 기존 실패 상태 fixture 검사도 유지한다. 미디어와 ASR 경계는 fake 입력이며 새 실마이크 시험은 아니다.

자체 리뷰에서 pending 저장을 음성 장치 활성화 전으로 옮겨 저장 실패 시 녹음이 먼저 시작되지 않게 했다. 결과 ID 저장 실패 시 이전 pending을 보존하므로 이전 지시로 진행할 수 없다. 추가 변경은 frontend뿐이라 backend/모델 재학습은 하지 않았다. PR #27/#28/#29는 이 수정을 통합한 뒤 각각 dev로 전환하여 검증·병합한다. 외부 최초 리뷰와 이 수정의 자체 검증을 구분한다.
