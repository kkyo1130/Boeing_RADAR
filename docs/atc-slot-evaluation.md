# 관제용 Whisper 전사의 BERT+규칙 추출 평가

이 실험은 [PR #25](https://github.com/kkyo1130/Boeing_RADAR/pull/25)의 관제용 Whisper 결과를 기존 BERT CALLSIGN + 규칙 ALT/HDG에 전달해 추출을 측정한다. 모델 재학습·규칙 보완·호출부호 사전 추가 없이 dev `d267d4b`의 구현을 사용한다. 원음은 실제 UWB-ATCC 교신이며, 이번 실험의 기본 입력은 이미 고정된 전사다.

## 자료와 정답

기존60개는 모두 TWR 교신이며 명시된 목표 고도·방위가0개였다. 활주로 번호, 풍향, 주파수, squawk 숫자는 목표 ALT/HDG가 아니다. 따라서 이60개에서 고도·방위 정확도를100%라고 계산하지 않는다. 호출부호가 명확한51개, 없는8개, 단독 `calibra`의 의미가 불명확한1개로 나눴다. 마지막1개는 CALLSIGN 점수에서 제외하되 고도·방위 부재 검사는 유지한다.

평가 라벨은 원본 코퍼스 전사를 읽고 BERT 추론 전에 작성했다. 호출부호는 해당 원문의 부분 문자열인지 확인했다. 숫자 값은 원문을 해석해 따로 붙이며, 평가 대상 규칙의 출력으로 정답을 생성하지 않는다. 이는 어시스턴트의 전사 기반 라벨 검토이며 원음을 다시 듣고 항공 전문가가 독립 검수한 라벨은 아니다. 원문 철자 오류와 생략 표현은 그대로 보존한다. [정답 라벨](evaluation/atc-slot-gold-2026-11-10.json)

추가 자료는 고도15개와 숫자 방위13개로 고정했다. 고도15개는 이전에 사용한 원본 그룹을 모두 제외했다. 방위는 그 조건에서 후보가0개였고, BERT 학습400개·검증99개의 원본 그룹과 기존 사용 ID를 제외하면 완전한 숫자를 가진23개/22그룹(학습만 제외),14개/13그룹(학습·검증 제외)이 남았다. 후자를 원본당1개씩 선택했다. 방위13개는 이전 시험 자료와 원본 그룹이 겹치므로 독립 새 시험이 아닌 별도 진단이다. 이 변경은 새 ASR와 BERT 추론 전에 결정했다. UWB의 `train`이라는 배포 분할 이름은 이번 RADAR 학습에 사용했다는 뜻이 아니다. 실제 BERT 가중치의 SHA-256이 `real-model-comparison-20261109/bert-seed13/model`과 같은 것을 확인하고 해당 `data.json`의 train/validation 분할을 감사했다. 고도와 방위의 제외 조건 차이는 결과에서 분리한다. 관제용 Whisper가 공개한 추가 학습 자료는 ATCO2+ATCOSIM이며 UWB가 아니다. 다만 Whisper 사전학습의 개별 파일 목록은 공개되지 않아 전체 비중복은 보장할 수 없다.

출처는 [UWB-ATCC](https://huggingface.co/datasets/Jzuluaga/uwb_atcc), revision `1e8270beb8c1643c8735dddb7229fffb0e399f74`, University of West Bohemia 제공·Jzuluaga 배포, CC BY-NC-SA4.0이다. 평가 전사·정답 파생자료에도 출처와 동일 라이선스 조건을 유지한다. 녹음과 가중치는 로컬에만 두고 Git에는 올리지 않는다.

## 무엇을 비교하는가

1. **정답 전사 → BERT+규칙:** STT 오류가 없는 기준 입력에서 추출기의 성능을 확인한다.
2. **관제용 Whisper 전사 → 같은 BERT+규칙:** 실제 받아쓰기 오류가 포함된 전체 연결의 추출 후보 성능이다.

호출부호는 BERT가 찾은 발화 문자열을 비교한다. 대소문자·공백·문장부호, 숫자 표기와 NATO 철자 표현만 정규화한다. 예를 들어 `German Wings 7P`와 `german wings seven papa`는 같게 보지만 `sierra say`를 `csa`로 고치지는 않는다. 항공사 이름을 ICAO 코드로 변환하거나 등록 항공기의 신원을 확정하는 평가가 아니다. 이 정규화는 채점에만 쓰며 모델 입력과 출력은 수정하지 않는다.

ALT/HDG는 기존 `parse_command`를 추출된 엔티티에 적용해 숫자로 변환한다. ALT는 feet, HDG는 degree이며 FL은100을 곱한다. 변환 실패 후보는 `UNRESOLVED`로 보존해 오검출로 센다. 잘못된 숫자는 FP와 FN을 각각1개로 센다. 같은 값이 두 번 나오면 중복 후보도 FP로 계산한다. 목표 값이 없는 문장의 올바른 빈 결과를 양성 재현율에 포함하지 않는다.

후단 전체 문장 문법·등록 호출부호 일치·음성 품질·지시 채택은 별도 단계다. 여기서는 엔티티/숫자 **후보 추출**을 측정하며 `issues`가 있으면 검토 필요 상태도 함께 보존한다. 후보 값이 맞았다는 이유로 그 지시가 승인됐다고 표현하지 않는다. 새 마이크 녹음, 서버 상태 변경, 운항 판단은 수행하지 않는다.

## 결과

아래는 해당 항목이 명시된 문장 중 **추출 목록 전체가 정답과 같은 개수**다. 정답을 찾았더라도 불필요한 호출부호/값이 추가되면 실패로 센다. 정규화한 발화 표현과 숫자 후보의 비교이며, 운영 지시 승인율은 아니다.

| 표본·항목 | 정답 전사 → BERT+규칙 | Whisper 전사 → BERT+규칙 |
| --- | ---: | ---: |
| 기존 TWR60: 호출부호 | 50/51 (98.0%) | 10/51 (19.6%) |
| 새 고도15: 호출부호 | 14/15 (93.3%) | 5/15 (33.3%) |
| 새 고도15: 고도 값 | 12/15 (80.0%) | 11/15 (73.3%) |
| 방위13 진단: 호출부호 | 7/7 (100%) | 0/7 (0%) |
| 방위13 진단: 방위 값 | 12/13 (92.3%) | 7/13 (53.8%) |

기존 TWR60은 ALT/HDG 양성0개이며 두 입력 조건 모두 해당 항목 오검출0/60이었다. 이는 활주로·풍향·주파수를 고도·방위로 잘못 뽑지 않았다는 검사이지, 고도·방위 양성 정확도100%가 아니다. 호출부호가 없는 TWR8개에서는 정답 전사로1개, ASR 전사로2개가 호출부호를 잘못 만들었다. `via one bravo` 같은 출발 절차 문구를 호출부호로 잡는 사례가 있다.

호출부호와 목표 숫자를 **함께** 맞힌 경우는 고도15개에서 정답 전사11/15→ASR4/15, 호출부호가 명시된 방위7개에서7/7→0/7이었다. 각 숫자만 맞힌 성능을 항공기와 지시 연결 성공으로 해석하면 안 된다. 추가 자료는 목표 필드가 있는 구간을 골랐고 표본도 작아서 실제 전체 교신의 발생 빈도나 정확도로 일반화하지 않는다.

## 실패 원인

**호출부호:** TWR의 ASR 실패41개 중39개는 정답에 해당하는 호출부호 표현이 ASR 문장 안에 없었다. 나머지2개는 정규화 표현이 있으나 BERT가 누락하거나 주변 단어까지 포함했다. 정답 전사에서는 성공하고 ASR에서 실패한 경우40개, 두 조건 모두 실패한 경우1개다. 이는 문자열 존재 여부에 따른 진단이며 원음 오류 원인을 별도로 청취 검증한 것은 아니다. 새 고도15개는 정답 표현 부재9개·추출 목록 오류1개·정확5개, 방위의 호출부호7개는 모두 정답 표현이 ASR에 없었다. 예: `csa seven three two two`가 `sierra say seven three two two ...`가 되면 BERT가 호출부호 구간을 찾아도 원래 문자열을 복원하지 못했다.

**현재 규칙/숫자 변환 한계:** 정답 전사에서도 고도3개와 방위1개가 변환되지 않았다.

- `flight level eight zero`: 정답8,000ft, 현재 파서는 FL을 세 자리로 요구해 거부한다.
- `flight level three hundred`: 정답30,000ft, 현재 FL 파서는 숫자를 자리별로 읽는 형식만 처리한다.
- `flight level three one zero one thousand or greater`: 목표31,000ft 뒤의 불완전한 rate 구문까지 고도 엔티티가 흡수돼 변환되지 않는다. 뒷부분을 임의 삭제해 정상 지시로 승인해서는 안 된다.
- `heading three six zero`: 정답은 북쪽을 RADAR의0–359 계약에 맞춘0°로 라벨링했다. 현재 파서는360을 범위 밖으로 거부하며0°로 정규화하지 않는다.

**추가 STT 영향:** 고도1개는 `one zero zero`를 `obama zero zero`로 받아 적어 고도 후보가 없어졌다. 방위5개는 `heading ah three one zero`, `heading kel two nine zero`, `heading q zero five zero` 같은 삽입 또는 `heading`→`leveling` 변경으로 후보를 놓쳤다. 남은 숫자가 보여도 문맥을 무시하고 값을 채워 넣지 않았다. 이번 숫자 실패는 값 누락/변환 불가였으며, 숫자 후보가 정상 변환됐지만 다른 정답 숫자로 나온 경우는 이 표본에서 없었다. 호출부호 오류는 별도로 남는다.

## 판단과 검증 범위

깨끗한 전사에서는 BERT가 호출부호를 잘 추출했지만 실제 ASR 전사에서는 이름·번호가 손상되는 것이 가장 큰 장애였다. 숫자 쪽에는 STT에서 명령어/숫자 사이로 단어가 끼는 문제와 기존 FL/방위 숫자 형식 지원 범위가 함께 남았다. 이번에는 원인을 측정했으며 모델·규칙을 수정해 재시험 점수를 올리지는 않았다.

최종88개×정답/ASR2조건으로 실제 BERT 추론176회, 추가 실제 음성28개의 관제용 Whisper 추론을 완료했다. 그 전에 기존 TWR60개만으로 한120회 예비 추출은 최종 평가 수에 중복 합산하지 않는다. 전용 단위 테스트6개, Python 컴파일, 입력/가중치/정답/전사 해시·결과 커버리지·제외 조건·채점 재계산 감사를 통과했다. [전체 후보·전사·검토 사유·실측 JSON](evaluation/atc-slot-results-2026-11-10.json)에 근거를 보존한다. 추가28개의 정답 라벨 해시가 ASR 실행 전 기록과 동일함을 확인했다. 외부 전문가 검수, 실제 마이크 재수음, 운영 서버 채택/전체 UI 회귀는 미실행이다.


## 구현·재현

- `scripts/evaluation/prepare_slot_audio.py`: 원본 그룹 제외 후 명시적 숫자 고도/방위 구간을 선정한다. 두 train parquet shard가 모두 준비돼야 한다. seed20261111, `_AT` 역할, 혼합 ALT/HDG 제외와 숫자 명시 조건을 고정한다. 처음에는 첫 shard에 숫자 방위가 없었고, 전체 shard 확인 후 이전 사용 그룹 제외 조건으로도0개임을 확인해 위 진단 조건으로 수정했다. 모델 결과를 보고 표본을 바꾸지는 않았다.
- `scripts/evaluation/evaluate_atc_slots.py`: 정답/ASR 두 조건에서 실제 BERT 가중치로 추론하고 기존 숫자 파서로 변환한 뒤 비교한다. 정답 라벨이나 예상 호출부호는 추론 함수에 전달하지 않는다.
- `scripts/evaluation/test_atc_slots.py`: 숫자/호출부호 정규화, 잘못된 값의 FP/FN, 음성 지시가 없는 표본의 미정 지표, 변환 실패·중복, 애매한 정답 제외를 검사한다.

원음·가중치·중간 결과는 `.demo/slots/`와 선행 worktree에 보존한다. 공개 결과에는 데이터/전사/정답/가중치의 해시와 표본별 원문·실제 후보·검토 사유를 기록한다.

실행 명령(작업 worktree 루트):

```sh
.venv/bin/python scripts/evaluation/transcribe_slot_supplement.py
.venv/bin/python scripts/evaluation/evaluate_atc_slots.py \
  --gold docs/evaluation/atc-slot-gold-2026-11-10.json \
  --prior ../atc-unseen-whisper/docs/evaluation/unseen-atc-whisper-2026-11-10.json \
  --supplement .demo/slots/supplement-asr.json \
  --model ../bert-hybrid-stt/.demo/bert-hybrid-model \
  --output .demo/slots/results.json
.venv/bin/python scripts/evaluation/publish_atc_slots.py
.venv/bin/python -m unittest discover -s scripts/evaluation -p 'test_atc_slots.py'
```

기존60개와 추가28개 모두 앞선 시험의 관제용 Whisper 설정(CPU int8/4 threads, 영어/beam5/VAD/temperature0/일반 안내문)을 사용한다. 이전14개 실패 구간의 재시도 결과를 이번60개에 섞지 않았다. 새28개는 원음 파일 직접 입력이며 새 스피커→마이크 녹음이 아니다.
