# 노트북 중간시연 콘솔

노트북에서 장치 연결·ROI·관제 재생·복창 녹음·검증을 조작한다. 기존 `/operations`에 추가된 로컬 시연 기능이며 `RADAR_DEMO_ENABLED=1`일 때만 입력 API를 연다. 실제 항공 운용용이 아니다.

## 실행

macOS, Python 3.12, Node 22.20+ 또는 24.12+, Xcode command line tools가 필요하다. 저장소 루트에서 최초 한 번 `sh scripts/setup-demo.sh`, 이후 `sh scripts/run-demo.sh`를 실행한다. 최초 설치는 공개 Whisper base.en 모델을 다운로드하며, 녹음은 로컬 모델에서 처리한다. 실행 주소는 `http://127.0.0.1:5175/operations`, API는 8001이다. Ctrl-C로 실행을 종료한다. 모델·생성 ATC WAV·DB는 ignored `.demo/`에 저장한다. 실행 중인 기존 MCP 5173 서버는 건드리지 않는다.

1. 호출부호 `RADAR123`으로 새 비행을 시작한다. 이전 서버의 비행 ID는 사용하지 않는다.
2. 아이패드 MCP 화면을 켜고 자동 잠금을 끈다. 카메라·아이패드 위치를 고정한다.
3. 카메라 연결 후 장치 목록에서 `ABKO APC930`을 선택하고 필요하면 다시 연결한다. 마이크도 원하는 USB 장치를 선택하고 연결한다. 입력 레벨을 확인한다.
4. **영역 설정 / 다시 지정**을 눌러 정지한 카메라 영상에서 ALT 숫자만 드래그하고 HDG 숫자만 드래그한다. 라벨·다른 숫자를 넣지 않는다. **연속 OCR 시작**을 누른다.
5. **관제 재생 및 지시 등록**을 누른다. ATC는 사전 등록 문구와 WAV를 사용하며 음성에서 추출한 관제라고 표시하지 않는다.
6. 서버 관제 표시 후 **복창 녹음 시작**, 아래 문장을 말하고 **녹음 종료 · 검증**을 누른다. 최대 29초 후 자동 종료하며 인식 중에는 재입력을 막는다.

`Radar one two three climb and maintain three thousand feet heading two seven zero`

7. 실제 인식 문장과 아래 서버 판정을 확인한다. 복창 오류는 새 녹음으로 수정한다. 카메라 설정 오류는 아이패드 숫자를 직접 바꾸고 새 관측을 기다린다. 모든 최종 판정은 기존 v2 서버가 담당한다.
8. **음성 안내 켜기**로 기존 보조 알림을 사용할 수 있다. 관제 재생·복창 녹음은 audioFocus 예약을 통해 안내·근거 음성을 중단한다. **END FLIGHT** 후 기록·리포트를 확인한다.

## 시연 순서

- 정상: 등록 관제3000/270 → 같은 내용 복창 → 아이패드3000/270.
- 복창 불일치: 관제3000/270 → heading290으로 복창 → 새 녹음에서270으로 수정.
- 설정 불일치: 같은 관제·올바른 복창 → 아이패드3500/270 → 3000/270으로 직접 수정. 서버의 설정 대기 시간이 포함된다.
- 판독 보류: 숫자 창 가림 또는 화면 꺼짐 → 원래 화면 복구. 근거 영상과 사유 확인.

## 실험 설정과 한계

- 영어의 기존 제한 문법만 지원한다. 호출부호 선두, `maintain ... feet`, `heading ...`를 사용한다. 미지원 표현·누락·낮은 점수·무음은 보류한다. 수정된 텍스트를 실제 발화처럼 보내는 기능은 없다.
- 호출부호 별칭 `Radar one two three`, `Radar 123`, `Radar 1-2-3`만 등록한다. 원문을 보존하면서 숫자의 천 단위 쉼표만 문법 검사에서 정규화한다.
- Whisper와 OCR 모델 점수는 정확도/확률이 아니다. 음성 .5, 영상 .5, RMS .01, clipping1%, 연속3회, 프레임5초, 조회 시 카메라 무응답6초는 실험 설정이다. 비교용 음성 관측 수명120초이며 오래된 복창은 다시 입력한다. 등록 ATC에는 모델 점수를 만들지 않으므로 서버 공통 점수 문턱은 null이고 실제 입력 어댑터에서 점수 문턱을 적용한다.
- 패널 추적은 숫자 영역을 제외한 주변 영상으로 ±60pixel 이동만 찾는다. 상관계수 .8 미만이면 `panel_tracking_lost`로 보류한다. 카메라 이동·회전·줌은 영역 재설정 대상이다. 반복 무늬 오매칭·드라이버의 동일 영상 반복은 완전히 감지하지 못한다. 수동 ROI와 자동 추적은 보조 도구이며 오인식 가능성이 있다.
- 한 세션600프레임 제한. 근거는 비행 소유 DB에 저장한다. 영상은 브라우저 수신/캔버스 촬영 시각이며 센서 노출시각이 아니다.
- 브라우저 탭을 숨기면 입력을 중단한다. 마이크 미리보기 연결만으로 음성은 저장하지 않으며 녹음 버튼으로 구간을 저장한다.
- 현재 범위는 사전 등록 ATC + 실제 복창 + 실제 카메라를 연결하는 시연이다. 스피커 ATC를 공유 마이크로 다시 수음·STT하는 본래 전체 AC와 SDR 연동은 완료로 주장하지 않는다.

## 확인 기록 · 2026-10-23

- 브라우저에서 ABKO 실제 영상·장치 선택·ROI 드래그·연속 프레임 전송 확인. 아이패드 화면이 꺼진 경우 `no_text`/null 확인. 마이크 장치 목록·실제 입력 레벨 확인.
- 합성 ATC WAV를 실제 로컬 Whisper와 HTTP API에 입력: `Radar 1-2-3 climb and maintain 3,000 feet heading 270.` 인식, 모델 점수 약.666, warm 실행 약1.69초, 복창 세 항목 NORMAL. 이는 파일 시험이며 실제 사용자 마이크 복창 성공으로 계산하지 않는다.
- 실제 촬영의 Safari 주소창 펼침/접힘 이미지로 패널 이동 확인. 자동 추적의 일반 성능 평가가 아니다.
- 실제 사용자의 복창→설정 변경→해결까지 전체 시연은 인수 시험으로 남는다. ROI·장비 상태를 먼저 확인하고 위 순서를 수행한다.
