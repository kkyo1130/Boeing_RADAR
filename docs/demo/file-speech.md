# 마이크 없이 관제·복창 음성 파일로 테스트

운영 화면: http://127.0.0.1:5179/operations . 기존 원본 ZIP의5178 화면에는 이 버튼이 없다.

1. 비행을 시작하거나 현재 비행을 연다. 호출부호가 음성 파일의 호출부호와 같은지 확인한다.
2. **마이크 없이 음성 파일로 판정**에서 **① 관제 음성 파일**을 선택한다.
3. **관제 파일 STT · 지시 등록**을 누른다. 관제 STT 문장과 서버 ALT·HDG 목표값을 확인한다. 미채택/판단 보류면 다음 복창 버튼은 활성화되지 않는다.
4. **② 조종사 복창 음성 파일**을 선택하고 **복창 파일 STT · 비교**를 누른다. 방금 채택된 관제의 atc_input_id에 연결한다. 처리 중 관제가 바뀌면 새 지시에 대해 다시 전송한다.
5. 아래 **복명복창**의 일치/불일치/판단 보류 및 STT 문장을 확인한다. **설정 확인**은 별도 최신 카메라 관측이 필요하므로 음성 일치만으로 정상 처리되지 않는다.

지원: WAV·MP3 및 브라우저가 지원하는 M4A 등. 파일당0.1–30초·10MB 이하. 한 파일에 한 역할의 발화만 넣고, 긴 교신은 관제/복창 구간별로 자른다. 마이크 연결·허용·스피커 재생은 필요 없다. 기존 ‘선택 파일 재생 + 마이크 수음’과 다른 직접 업로드 기능이다.

예를 들어 DELTA123 비행이라면 관제/복창 파일 각각에서 `Delta one two three, climb and maintain three thousand feet, heading two seven zero`를 말할 수 있다. 파일의 호출부호가 다른 항공기면 현재 비행의 지시로 확정하지 않는다. 브라우저에서 파일을 읽지 못하면 WAV 또는 MP3로 변환해 다시 시도한다.

## 처리 경로

브라우저의 OfflineAudioContext가 파일을 디코딩하고 실제 채널을 평균해 mono PCM16/16kHz WAV로 변환한다. 재생·마이크 재수음·자동 원고 대입은 하지 않는다. ATC/PILOT 전용 버튼이 각각 `/api/demo/{flight}/atc`, `/readback`에 `input_mode=file_upload`로 보내고 서버의 로컬 Whisper→BERT/문법 검사→기존 판정 엔진으로 처리한다. UI는 서버 결과만 표시한다. 파일 접수 구간 시각은 HOST_RECEIVE이며 원래 녹음 시각을 추정하지 않는다.

원본 음성 근거는 기존 media/segment/observation 경로에 저장한다. role_basis는 ATC_FILE_UPLOAD 또는 PILOT_FILE_UPLOAD로 기록해 물리 마이크 입력과 구분한다. 기존 MICROPHONE 채널은 논리 음성 입력을 포함하는 계약이며, 파일 처리 성공이 물리 마이크 연결을 뜻하지 않는다. 파일 인식 점수는 보정된 정확도가 아니다. 무음·불명료·모델 실패·잘못된 지시 연결은 판단 보류/오류로 유지한다.
