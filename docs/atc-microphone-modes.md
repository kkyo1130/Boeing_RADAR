# ATC 수음 / 파일럿 복창 모드

실제 관제 녹음을 재생해 마이크로 받고, 현재 채택된 지시에 대해 조종사가 별도로 복창하는 시연 경로다. 음색이나 발화 순서로 화자를 추정하지 않는다. 사용자가 고른 입력 모드가 역할의 근거다. 실제 무선 수신기와의 연결 또는 녹음 안의 화자 분리는 구현하지 않았다.

## 사용 순서

1. 기존 로컬 데모 실행 설정으로 서버와 `/operations` 화면을 연다. `RADAR_DEMO_ENABLED=1`, `RADAR_WHISPER_MODEL`, `RADAR_NER_BACKEND=bert-hybrid`, BERT 모델 경로인 `RADAR_NER_MODEL`이 필요하다. 비행 호출부호와 허용 발음은 서버 설정에 먼저 등록한다.
2. 마이크를 연결하고 **ATC 수음**을 선택한다. PC 스피커 음소거를 해제한다. 녹음 속 호출부호가 현재 비행과 맞아야 한다.
3. 28초 이하의 관제사 발화 파일을 선택해 **선택 파일 재생 + 마이크 수음**을 누른다. 파일은 브라우저 스피커에서 재생되고, 서버로 전송되는 것은 선택한 마이크가 새로 녹음한 PCM WAV다. 원본 파일이나 정답 전사를 직접 STT에 넣는 버튼이 아니다. 헤드폰 재생은 내장 마이크에 소리가 전달되지 않을 수 있다.
4. 파일 재생이 끝나고 0.5초 뒤 수음을 종료한다. 외부 기기에서 재생하려면 파일 선택 없이 **ATC 수음 시작 → 녹음 종료·검증**을 사용한다. 29초 제한 도달 시 취소하고 다시 수음한다. 제한으로 잘린 음성을 완료 발화로 제출하지 않는다.
5. 인식 문장과 서버의 지시 채택 결과를 확인한다. ATC가 채택되면 **파일럿 복창** 모드에서 별도 녹음을 시작한다. 해당 ATC ID에 연결해 비교한다. 실패한 새 관제 대신 이전 지시에 복창하는 버튼은 차단한다.

녹음·처리 중에는 모드를 변경할 수 없다. ATC에서는 스피커 음성을 지우지 않도록 브라우저 echo cancellation/noise suppression을 끄고, 파일럿에서는 다시 켠다. 브라우저·장치별 실제 처리는 다를 수 있다. 이전 정상 복창은 새 입력 시작의 health 이벤트에서 해제되며, 화면도 새 ATC 확인 전까지 판단 보류한다. 취소·장치 끊김·연결 끊김은 이전 결과를 새 결과로 확정하지 않는다.

기존 사전 등록 관제 버튼은 예비 시나리오로 남겨두었고 **ATC STT 사용 안 함**을 표시한다.

## API와 저장

`POST /api/demo/{flight}/atc`는 `audio`(base64 PCM WAV), UTC `started_at`/`ended_at`, `input_mode`를 받는다. `input_mode`는 `microphone_playback` 또는 진단용 `file_upload`다. 호출자가 전사문·역할·기존 ATC ID를 넣으면 거절한다. 로컬 데모용 입력 모드 표시는 클라이언트의 선언이며 녹음 출처를 인증하는 장치는 아니다.

서버가 새 ATC segment/attempt/input ID와 `ATC_PLAYBACK` 역할 근거를 만들고 원본 수음 WAV를 근거 저장소에 저장한다. 실제 Whisper 전사 → BERT 호출부호 후보 + 숫자/명령 규칙 → 등록 호출부호/구조/품질 검사 → 지시 채택 또는 보류 순서다. `POST .../readback`은 기존대로 현재 `atc_input_id`를 요구하고 `PILOT_PTT` 역할을 만든다. 원음과 전사는 근거로 보존되며, 숫자나 호출부호를 정답으로 교체하지 않는다.

ASR 사용 중 중복 요청은 미디어나 새 ATC를 저장하기 전에 409로 거절한다. ASR 장애·불명확한 문장·조건부 명령은 판단 보류한다. 부분적으로 알아들은 방위만으로 잘못된 호출부호의 지시를 채택하지 않는다.

## 실제 관제 녹음 시험 — 2026-11-10

출처는 [UWB-ATCC의 Hugging Face 배포본](https://huggingface.co/datasets/Jzuluaga/uwb_atcc)이다. University of West Bohemia의 실제 교신 중 관제사 표시 `_AT`가 있는 짧은 방위 지시 3개를 **추론 전에 고정**했다. 라이선스는 CC BY-NC-SA 4.0이다. 원본 WAV/모델/DB는 Git에 넣지 않았다. source revision·ID·해시·ASR 원문·보류 사유는 [시험 기록](evaluation/atc-playback-2026-11-10.json)에 있다.

| `1a67h9_000000_000314_AT` | 300 | 호출부호 오인식, 보류 | 짧은 오인식 문장, 보류 |

- 원음 파일 3개: 새 지시 채택 **0/3**. 실제 MacBook Air 스피커 → 내장 마이크 3개: 채택 **0/3**. 모두 `LATEST_ATC_NOT_ADOPTED`, ALT/HDG 목표값 없음, 복창 요구 없음이었다.
- 첫 하드웨어 시도에서는 OS 출력 음소거를 발견했다. 해당 결과를 성공 수음 사례에서 제외했다. 음소거 해제·볼륨50으로 다시 시험했고 수음 RMS는 0.0223 / 0.0154 / 0.0236이었다. 끝나면 기존 볼륨13·음소거를 복원했다. 임계값은 낮추지 않았다.
- 실제 마이크 시험은 Python/Core Audio로 원음을 스피커 출력하면서 물리 마이크를 녹음해 새 API에 제출했다. 브라우저의 버튼/자동종료/모드 전환은 별도 fake-device 테스트로 검증했다. 실제 브라우저 마이크 E2E, 새로운 조종사 육성 복창, 카메라까지의 전체 E2E는 이번에 수행하지 않았다.
- 자료는 원 데이터의 train split이다. 학습 중복을 감사하지 않았으므로 독립 시험 정확도나 일반화 성능으로 해석하지 않는다. ATCO2 평가자료는 사용하지 않았다.

입력 경로는 연결됐지만 이번 실제 무전 녹음에서 정확한 지시 추출은 달성하지 못했다. 원음 파일도 실패하므로 먼저 ATC 음성에 대한 STT 성능을 비교해야 한다. 다음 실험은 같은 음원의 별도 평가 목록을 고정한 뒤 다른 STT 모델과 전처리를 비교하는 것이다. BERT 재학습만으로 음성→텍스트 오류가 해결된다고 결론내리지 않는다.
